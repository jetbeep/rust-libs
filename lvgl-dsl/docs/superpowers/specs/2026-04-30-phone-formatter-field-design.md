# PhoneFormatterField — Design

Status: approved for planning
Crate: `lvgl-dsl`
Target: `no_std` + `extern crate alloc` (Zephyr embedded + desktop-sim)
LVGL version: 9.2.x

## 1. Problem & Goals

Add a reusable formatted input field for phone numbers and simple numeric codes.
The field should render as one rounded, bordered input; optionally include a
customizable left action slot; and actively format user-entered digits as the
user types.

The primary examples are:

- a phone field with a left country selector and `+41 86 602 93 71` formatting;
- a simple numeric code field with `WECHIP - 2 3 4 5 6 7` formatting.

### In scope

- A new exported `PhoneFormatterField` composite widget.
- Active live formatting from digit-only raw input to formatted display text.
- Formatter presets from both `prefix + groups` and mask strings with `X`
  placeholders.
- Optional built-in left slot with common presets and custom content support.
- Support for external composition by omitting the built-in slot.
- Raw and formatted value accessors.
- Desktop/mock bindings, spy calls, and unit tests matching existing patterns.
- `DSL_REFERENCE.md` and `DSL_PLAYGROUND.html` updates.

### Out of scope

- Full international phone-number validation.
- Country metadata databases or automatic country detection.
- Arbitrary free-text input inside this field.
- Multi-line text input.
- Replacing the generic `TextArea` widget.

## 2. Public API

`PhoneFormatterField` will behave like a normal DSL widget by implementing
`Widget` on its root container. Existing size, alignment, border, color, radius,
font, opacity, and event helpers will therefore work on the whole field.

Example:

```rust
use lvgl_dsl::lvgl::prelude::*;

let phone = PhoneFormatterField::new(
    &screen,
    FormatPreset::groups("+41 ", &[2, 3, 2, 2]),
)
.left_slot(
    LeftSlot::preset()
        .text("🇨🇭")
        .arrow("▾")
        .width(Size::Px(72))
        .divider(true),
)
.placeholder_text("+41 XX XXX XX XX")
.size(Size::Px(340), Size::Px(56))
.radius(CornerRadius::Px(8))
.border_width(2);

phone.set_raw_digits("866029371");
assert_eq!(phone.raw_digits(), "866029371");
assert_eq!(phone.formatted_text(), "+41 86 602 93 71");

let code = PhoneFormatterField::new(
    &screen,
    FormatPreset::mask("WECHIP - X X X X X X"),
)
.placeholder_text("WECHIP - X X X X X X");
```

Proposed core types:

```rust
pub struct PhoneFormatterField { /* root + children + formatter state */ }

pub enum FormatPreset {
    Groups { prefix: alloc::string::String, groups: alloc::vec::Vec<usize> },
    Mask { mask: alloc::string::String },
}

pub struct LeftSlot { /* preset content and styling */ }

pub struct LeftSlotHandle { /* custom-content escape hatch */ }
```

`FormatPreset::groups(prefix, groups)` will be the direct representation for
phone-style grouping. `FormatPreset::mask(mask)` will parse `X` as digit slots
and every other character as generated literals. Both forms expose the same
formatter behavior after construction.

## 3. Architecture

Use a composite widget:

1. `PhoneFormatterField` owns a root `Obj` container.
2. The root uses row layout and field-level styling.
3. If configured, the root creates a left-slot `Obj` or `Button` segment.
4. The left slot contains preset children or caller-provided custom children.
5. A one-line `TextArea` fills the remaining width.
6. The text area is styled borderless and transparent so the root reads as one
   field.
7. A value-changed trampoline normalizes and formats text input.

This follows the existing composite-widget direction used by richer DSL
components while reusing `Obj`, `Button`, `Label`, `Image`, and `TextArea`
wrappers.

## 4. Formatting Behavior

The widget stores raw input as digits only. Prefixes, spaces, separators, and
mask literals are generated by the formatter and are never part of the raw
value.

On user edits:

1. Read the current text-area content.
2. Strip every non-ASCII digit.
3. Truncate to the preset capacity.
4. Render formatted display text from the raw digits.
5. Write the formatted text back to the text area if it changed.

Partial values format progressively. A `groups("+41 ", &[2, 3, 2, 2])` preset
with raw `8660` displays `+41 86 60`; a `mask("WECHIP - X X X X X X")` preset
with raw `234` displays `WECHIP - 2 3 4`. Empty fields can show placeholder
text such as `+41 XX XXX XX XX` or `WECHIP - X X X X X X`; the actual text
content remains empty until raw digits exist.

Public setters use the same normalization and truncation path as user edits.
This keeps programmatic updates and keyboard input consistent.

## 5. Left Slot Customization

The built-in left slot supports common presets and a custom-content escape
hatch.

Preset options include:

- optional image/icon;
- optional text label;
- optional arrow indicator;
- fixed or content-driven width;
- divider enabled/disabled;
- padding, colors, and text styles;
- click callback.

For custom layouts, callers can request a left-slot container handle and add
their own child widgets, such as `Image`, `Label`, or other LVGL wrappers. The
field still owns root layout, divider treatment, and text formatting. For full
external composition, callers omit the built-in slot and place their own button
or selector next to the field.

## 6. Validation and Errors

Construction panics with clear messages for invalid formatter definitions,
matching existing DSL misuse checks:

- group presets with no groups;
- group sizes of zero;
- masks with no `X` digit slots;
- presets with zero total digit capacity;
- left-slot preset configuration that enables a slot without any preset content
  or custom-content builder.

Ordinary runtime input does not panic. It normalizes, truncates, and formats.
Programmatic setters follow the same behavior.

## 7. Bindings and Tests

The real Zephyr path will rely on bindgen for existing LVGL symbols. The
desktop/mock path may need additional spy coverage for text-area edit helpers
and child layout/style calls used by the composite widget.

Unit tests will cover:

- group preset formatting, including partial input;
- mask preset formatting, including partial input;
- digit-only normalization;
- truncation to preset capacity;
- `set_raw_digits`, `raw_digits`, and `formatted_text`;
- empty content plus placeholder behavior;
- optional left-slot creation;
- preset left-slot text/icon/arrow children;
- custom left-slot container access;
- left-slot click registration;
- export through `lvgl::mod` and `lvgl::prelude`.

## 8. Documentation and Playground

`DSL_REFERENCE.md` will add `PhoneFormatterField` to the widget list and include
examples for the `+41` phone field and the `WECHIP - X X X X X X` simple-number
field.

`DSL_PLAYGROUND.html` will add a configurable section for:

- choosing group or mask preset mode;
- editing prefix, group sizes, or mask text;
- enabling/disabling the built-in left slot;
- configuring common left-slot content;
- previewing raw and formatted values;
- generating example DSL code.
